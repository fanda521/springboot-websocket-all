方式 1：JSR 356 原生 WebSocket（JavaEE 标准）
1. 核心 API 与注解（通用）
JSR 356 是 JavaEE 7（2013）推出的官方 WebSocket 标准，所有兼容容器（Tomcat 7+/Jetty 9+/WildFly 8+）均实现了该规范，核心 API 集中在 javax.websocket 包：
核心类 / 注解	作用
@ServerEndpoint	标注类为 WebSocket 服务端点，指定访问路径（如 @ServerEndpoint("/ws/chat")）
@OnOpen	连接建立时触发的方法，参数可注入 Session（会话）、EndpointConfig（配置）
@OnMessage	接收客户端消息时触发，支持文本（String）、二进制（ByteBuffer）、Pong 帧
@OnClose	连接关闭时触发，参数可注入 CloseReason（关闭原因）
@OnError	连接异常时触发，参数注入 Throwable（异常）
Session	会话对象，用于发送消息（getBasicRemote()/getAsyncRemote()）、管理连接
RemoteAsync	异步发送消息（非阻塞），避免同步发送阻塞线程
ServerEndpointConfig	自定义端点配置（如跨域、拦截器）


2.版本差异（容器 / JavaEE 版本）
版本 / 容器	核心差异
JavaEE 7（JSR 356）	首次推出标准，仅支持基础功能（文本 / 二进制帧、基本注解），无分片帧高级处理
JavaEE 8（JSR 356 1.1）	新增 PongMessage 支持、Session.getRequestParameterMap() 等便捷 API
Tomcat 7.x	仅支持 JSR 356 基础版，不支持异步发送优化
Tomcat 8.x/9.x	完整支持 JSR 356 1.1，优化线程模型，支持大帧分片
Tomcat 10.x	包名变更：javax.websocket → jakarta.websocket（Jakarta EE 9+）
Jetty 9.x	兼容 JSR 356，自定义配置更灵活（如连接超时、帧大小限制）
3. 关键注意事项
Tomcat 10+ 兼容问题：JavaEE 迁移到 Jakarta EE，所有 javax.websocket 包需替换为 jakarta.websocket；
线程安全：Session 是非线程安全的，多线程发送消息需加锁；
依赖引入：非 JavaEE 容器（如 Spring Boot 内嵌 Tomcat）需手动引入依赖：
xml
<!-- Spring Boot 中引入 JSR 356 依赖 -->
<dependency>
    <groupId>javax.websocket</groupId>
    <artifactId>javax.websocket-api</artifactId>
    <version>1.1</version>
    <scope>provided</scope>
</dependency>



方式 2：Spring WebSocket（Spring 封装）
Spring WebSocket 是 Spring 4.0（2013）推出的封装层，底层兼容 JSR 356，同时扩展了 STOMP 协议、消息代理等高级功能，适配 Spring 生态。
1. 核心 API 演进（按 Spring 版本）
（1）Spring 4.x 核心 API（基础版）
核心类 / 注解	作用
@EnableWebSocket	启用 WebSocket 支持（配置类注解）
WebSocketConfigurer	配置接口，注册 WebSocketHandler
WebSocketHandler	核心处理器，替代 JSR 356 注解，自定义消息处理逻辑
TextWebSocketHandler	文本消息处理器（简化 WebSocketHandler 实现）
BinaryWebSocketHandler	二进制消息处理器
WebSocketSession	Spring 封装的会话对象，兼容 JSR 356 Session
SockJsService	SockJS 降级支持（兼容低版本浏览器，自动切换长轮询）
（2）Spring 5.x+ 增强 API（响应式）
新增类 / 注解	作用
@EnableWebSocketMessageBroker	启用 STOMP 消息代理（支持订阅 / 发布、主题路由）
StompEndpointRegistry	注册 STOMP 端点，支持 SockJS
SimpMessagingTemplate	消息模板，简化广播、点对点消息发送
@MessageMapping	映射客户端消息（类似 @RequestMapping）
@SendTo	广播消息到指定主题
ReactorNettyWebSocketHandler	响应式 WebSocket 处理器（基于 Reactor Netty，非阻塞）
2. 版本差异（Spring 4.x vs 5.x vs 6.x）
Spring 版本	核心差异
4.0-4.3	仅支持基础 WebSocketHandler，无 STOMP 高级功能，依赖 JSR 356 容器
5.0+	1. 新增响应式编程支持（Reactor Netty）；
2. 完善 STOMP 协议支持；
3. 兼容 Servlet 3.1+ 和 Reactive 容器；
4. 支持 WebSocketSession 异步处理
6.0+（Spring Boot 3.x）	1. 基于 Jakarta EE 9+，包名从 javax 改为 jakarta；
2. 移除对 SockJS 1.x 兼容；
3. 强化 Reactive 优先，性能提升 30%+



方式 3：Netty WebSocket（手动实现）
Netty 是无容器依赖的 NIO 框架，完全自定义 WebSocket 协议处理，适合高性能、分布式场景。
1. 核心 API（Netty 4.x+）
核心类 / 组件	作用
WebSocketServerProtocolHandler	Netty 内置的 WebSocket 协议处理器（处理握手、帧解析）
HttpServerCodec	HTTP 编解码器（处理 WebSocket 握手的 HTTP 请求）
HttpObjectAggregator	聚合 HTTP 请求（完整读取握手请求）
TextWebSocketFrame	文本帧对象
BinaryWebSocketFrame	二进制帧对象
ChannelPipeline	处理器管道，添加编解码、业务处理器
SimpleChannelInboundHandler	简化的 ChannelHandler，泛型指定帧类型
2. 版本差异（Netty 4.x 系列）
Netty 版本	核心差异
4.0.x	基础 WebSocket 支持，帧解析需手动处理分片
4.1.x+	1. 优化 WebSocketServerProtocolHandler，自动处理分片帧；
2. 新增 ReplayingDecoder 简化帧解析；
3. 支持 HTTP/2 底层传输
3. 实战示例（Netty 4.1.x+）
java
运行
import io.netty.bootstrap.ServerBootstrap;
import io.netty.channel.*;
import io.netty.channel.nio.NioEventLoopGroup;
import io.netty.channel.socket.SocketChannel;
import io.netty.channel.socket.nio.NioServerSocketChannel;
import io.netty.handler.codec.http.HttpObjectAggregator;
import io.netty.handler.codec.http.HttpServerCodec;
import io.netty.handler.codec.http.websocketx.*;
import io.netty.handler.stream.ChunkedWriteHandler;

public class NettyWebSocketServer {
    private final int port;

    public NettyWebSocketServer(int port) {
        this.port = port;
    }

    public void start() throws InterruptedException {
        // Boss 线程组（处理连接建立）
        EventLoopGroup bossGroup = new NioEventLoopGroup(1);
        // Worker 线程组（处理 IO 读写）
        EventLoopGroup workerGroup = new NioEventLoopGroup();
        try {
            ServerBootstrap b = new ServerBootstrap();
            b.group(bossGroup, workerGroup)
             .channel(NioServerSocketChannel.class)
             .childHandler(new ChannelInitializer<SocketChannel>() {
                 @Override
                 protected void initChannel(SocketChannel ch) {
                     ChannelPipeline pipeline = ch.pipeline();
                     // HTTP 编解码
                     pipeline.addLast(new HttpServerCodec());
                     // 聚合 HTTP 请求（最大 64KB）
                     pipeline.addLast(new HttpObjectAggregator(65536));
                     // 大文件传输支持
                     pipeline.addLast(new ChunkedWriteHandler());
                     // WebSocket 协议处理器（指定端点路径）
                     pipeline.addLast(new WebSocketServerProtocolHandler("/ws/chat"));
                     // 自定义业务处理器
                     pipeline.addLast(new NettyWebSocketHandler());
                 }
             })
             .option(ChannelOption.SO_BACKLOG, 128)
             .childOption(ChannelOption.SO_KEEPALIVE, true);

            // 绑定端口，启动服务
            ChannelFuture f = b.bind(port).sync();
            f.channel().closeFuture().sync();
        } finally {
            workerGroup.shutdownGracefully();
            bossGroup.shutdownGracefully();
        }
    }

    // 自定义业务处理器
    public static class NettyWebSocketHandler extends SimpleChannelInboundHandler<WebSocketFrame> {
        // 处理文本帧
        @Override
        protected void channelRead0(ChannelHandlerContext ctx, WebSocketFrame frame) {
            if (frame instanceof TextWebSocketFrame) {
                TextWebSocketFrame textFrame = (TextWebSocketFrame) frame;
                String msg = textFrame.text();
                System.out.println("Netty 收到文本：" + msg);
                // 响应文本帧
                ctx.writeAndFlush(new TextWebSocketFrame("Netty 响应：" + msg));
            } else if (frame instanceof BinaryWebSocketFrame) {
                // 处理二进制帧
                BinaryWebSocketFrame binaryFrame = (BinaryWebSocketFrame) frame;
                System.out.println("收到二进制数据，长度：" + binaryFrame.content().readableBytes());
            } else if (frame instanceof CloseWebSocketFrame) {
                // 处理关闭帧
                ctx.writeAndFlush(frame.retain());
                ctx.close();
            }
        }

        // 连接建立
        @Override
        public void channelActive(ChannelHandlerContext ctx) {
            System.out.println("Netty 连接建立：" + ctx.channel().id());
        }

        // 异常处理
        @Override
        public void exceptionCaught(ChannelHandlerContext ctx, Throwable cause) {
            cause.printStackTrace();
            ctx.close();
        }
    }

    public static void main(String[] args) throws InterruptedException {
        new NettyWebSocketServer(8080).start();
    }
}
五、三种实现方式的版本兼容总结
维度	JSR 356 原生	Spring WebSocket	Netty WebSocket
最低 Java 版本	Java 7+（JavaEE 7）	Java 8+（Spring 4.x）	Java 8+（Netty 4.x）
包名变更	Tomcat 10+/Jakarta EE 9+：javax→jakarta	Spring 6.x：javax→jakarta	无包名变更，仅 API 优化
容器依赖	强依赖 Servlet 容器	弱依赖 Spring 容器	无容器依赖
版本兼容痛点	Tomcat 10+ 包名不兼容	Spring 5.x→6.x 跨域 API 变更	Netty 4.0→4.1 分片帧处理优化
性能	中（容器线程池限制）	中高（可切换 Reactive）	高（NIO 零拷贝、自定义线程模型）
六、选型建议
快速开发、Spring 生态：优先选 Spring WebSocket（5.x+），用 STOMP 简化消息路由；
标准兼容、轻量场景：选 JSR 356 原生 API，无需额外依赖；
高性能、分布式、自定义协议：选 Netty WebSocket，适合百万级连接场景；
版本升级注意：
从 Spring 5.x 升级到 6.x：替换 javax 为 jakarta，调整跨域配置；
从 Tomcat 9 升级到 10：JSR 356 包名同步改为 jakarta.websocket；
Netty 升级：优先选 4.1.x+，利用内置的分片帧处理优化。
